Modelling Our Data

Looking at our data, I want to design a model that can predict the amount of profit made off an order, meaning profit will be our response variable.

Prior to creating any models, I’m going to do the initial preparation work, including splitting the data into training and test sets.

# I'm going to fix the random number generation to allow the data to be reproducible
set.seed(3)

# Now, I'm going to split the data into training and test sets for fitting and testing our predictive models
store_split <- initial_split(store_parsed, prop = 0.7)
store_training <- training(store_split)
store_test <- testing(store_split)

# Create cross-validation data for evaluating our models
store_cv_folds <- vfold_cv(store_training, 5)

Because our response variable is a numeric variable, our model evaluation metric is going to be root mean square error (RMSE) to evaluate how our model does across all observations.

Since both of our models will use the same recipe, I’m going to create it in advance. For our predictors, I’d like to see how Discount, Product Sub-Category and Consumer Segment impact Profit, so I will set those as my predictor variables. These are some of the easier predictor variables to work with from the set and would likely have an impact on the ability to predict profit.

model_rec <- recipe(Profit ~ Discount + `Sub-Category` + Segment, data = store_training) |>
  # Since Segment and Sub-Category are categorical variables, I'll set them as dummy variables
  step_dummy(`Sub-Category`, Segment) |>
  # Our predictor, Discount, is a numeric variable, so I'm going to normalize the values.
  step_normalize(Discount)

Regression Tree

A regression tree is a type of predictive model that attempts to split up predictor space into regions. Because our response variable is numeric, our model will be a regression tree instead of a classification tree (which would be used with categorical response variables). The way that regression trees are made is that for each value of a predictor variable, the SSE is calculated. Whichever value has the lowest SSE is where a split will take place. This process is repeated until all predictor variables have been accounted for and the response variable is able to be predicted.

Since we’ve already created our recipe, the next steps are to define our model and engine and to create our workflow.

# Define model and engine
tree_mod <- decision_tree(tree_depth = tune(),
                          min_n = 20,
                          cost_complexity = tune()) |>
  set_engine("rpart") |>
  set_mode("regression")

# Create workflow
tree_wkf <- workflow() |>
  add_recipe(model_rec) |>
  add_model(tree_mod)

Now that the workflow has been created, I’m going to fit it to our cross-validation folds that we created earlier to tune the model.

tree_grid <- grid_regular(cost_complexity(),
                          tree_depth(),
                          levels = c(10,5))
tree_fit <- tree_wkf |>
  tune_grid(resamples = store_cv_folds,
            grid = tree_grid,
            metrics = metric_set(rmse))

Now that our model has been fit, I’m going to collect the metrics of the model and choose the one that has the best fit, meaning the lowest RMSE.

Random Forest

A random forest model is a model that involves the use of bootstrapping (resampling) and the creation of many regression trees from these bootstrapped samples. One of the major differences compared to the regression tree is that not all predictors are used at each step/ split. This model is able to consider a random subset of predictor variable each time a split needs to be made. The model with the best metric is then able to be selected. We might prefer a random forest model over a regression tree for a decrease in variability. With a normal regression tree, changes in the data can result in drastic changes in the tree. However, because bootstrapping is involved, the best model is selected taking into account that different data is being used to build the model. A random forest model would also be preferred over a normal regression tree because there’s no method to consider how the current split might impact future splits beyond the next immediate split.

As before, since the recipe has been established, now I’ll define our model and engine and create our workflow.

# Define model and engine
rand_mod <- rand_forest(mtry = tune()) |>
  set_engine("ranger", importance = "impurity") |>
  set_mode("regression")

# Create workflow
rand_wkf <- workflow() |>
  add_recipe(model_rec) |>
  add_model(rand_mod)

Now that the workflow has been created, I’m going to fit it to our cross-validation folds that we created earlier to tune the model.

rand_fit <- rand_wkf |>
